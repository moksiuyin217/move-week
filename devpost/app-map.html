MOVE WEEK · HOW THE APP FITS TOGETHER

From a file to a plan.

This is a short route through the code behind the page you tried. The browser reads the HTML, loads its CSS and JavaScript, and then runs the app directly—there is no compile or build step.

01

How the page is loaded

README.md starts a tiny Python web server. It serves the project files to the browser. In index.html, the stylesheet link controls appearance and the deferred script loads the app after the page is read.

<link rel="stylesheet" href="styles.css">
<script defer src="app.js"></script>

02

Where the screenshot enters

The image input is in index.html. In app.js, its change handler receives the chosen file and calls readImage. When OCR returns text, parseWorkouts turns name-and-duration lines into editable workout records.

input.addEventListener('change', async () => {
  const image = input.files?.[0];
  if (!image) return;
  await readImage(image);
});
index.html · #image-inputapp.js · readImage, parseWorkouts
03

How edits become the plan

renderWorkouts builds one row for each record. When a date, name, or time changes, the record is updated and renderPlan refreshes the visible text and downloadable calendar. The custom time picker is in makeWorkoutRow; createCalendarFile formats the .ics events.

field.addEventListener('input', () => {
  workout[field.dataset.field] = field.value;
  renderPlan();
});

A PRACTICE TO REUSE

Decide what “works” looks like before adjusting the control.

The time-picker requirement became observable: the menu shows exactly 00, 15, 30, and 45, manually entered minutes still update the plan, and the flow fits a 390px screen. For another feature, write down the visible outcome and the screen or input conditions that matter, then check those outcomes in the running page.

RUN IT AGAIN

See your change in the browser

From the project folder, run py -m http.server 8000, then open http://localhost:8000/. Edit the HTML for page structure, CSS for appearance, or JavaScript for behavior, then refresh.

PUBLISHING

From local files to a live site

GitHub Pages serves these same static files from the branch and root folder selected in repository Settings → Pages. The browser loads the page and its linked files at the public address; no build command is needed.
